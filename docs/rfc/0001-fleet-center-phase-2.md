# RFC：Fleet Center 第二階段營運情報與車隊管理功能擴充

## 1. 提案資訊

- 專案：https://github.com/jpnh09/fleet-center
- 類型：RFC / Feature Proposal
- 狀態：Draft — 待多模型技術審查
- 提案日期：2026-11-26
- 本輪範圍：可行性研究、架構評估、功能優先順序及實作建議
- 本輪不實作、不部署、不合併

## 2. 背景

Fleet Center 目前以 Frappe v15／ERPNext 為基礎，已具備車籍管理、日期提醒、站內通知、TDX 道路情報及政府 API 專用出口代理等功能。

現有架構已具備以下可重用能力：

- gov_egress.py：受控政府 API 出口代理。
- gov_gateway.py：ERP 端 API 介接。
- hooks.py：背景排程。
- road_events.py：道路事件同步、狀態比對與通知。
- road_events_core.py：可獨立測試的純邏輯。
- notification_dispatch.py：提醒通知及去重。
- 現有 Fleet Center 前端介面。
- 車籍權限及操作稽核機制。

依現有專案文件，正式 ERP 容器維持網路隔離，只有受控代理可以連線至核准的外部服務。正式部署狀態仍須由本機工程師確認。

本提案希望利用既有架構，逐步增加重件運輸、曳引車及半聯結車營運所需的功能，而不是重新建造另一套 ERP。以下官方來源均為待審查的研究入口，不代表已驗證所有端點、授權或免費額度。

## 3. 候選功能

### RFC-01｜NCDR 災害與強風預警

**目的**

補充 TDX 道路事件以外的預告性、災害性及氣象相關交通警戒。

**候選功能**

- 高速公路強風管制。
- 交流道淹水警戒。
- 豪雨與颱風示警。
- 道路相關災害警戒。
- 示警新增、更新、取消及有效期限管理。
- 與 TDX 重疊事件的關聯及通知去重。

**官方來源**

- https://alerts.ncdr.nat.gov.tw/web/
- https://alerts.ncdr.nat.gov.tw/web/developer/alerts-api
- https://alerts.ncdr.nat.gov.tw/api_swagger/index.html

**待研究事項**

- 新版 API Key 認證規範。
- 免費會員可取得的實際示警種類。
- CAP、JSON、Atom Feed 的適用性。
- 更新、取消及過期訊息的判定。
- 是否可以直接重用既有 gov-egress。
- 在不開放 ERP 入站連線的前提下，選擇輪詢或官方推送機制。
- 是否存在與 TDX 重複發布的事件。

**第一版建議**

優先採用受控 API 輪詢，不為接收推送而貿然開放 ERP 公網入口。

### RFC-02｜大貨車與聯結車禁行公告監控

**目的**

監控各地方政府對大貨車、曳引車及聯結車的道路管制公告，避免承辦人遺漏新規定。

**候選功能**

- 官方公告定期查詢。
- 新舊公告版本保存。
- 公告內容及附件異動比對。
- 生效日期與發布日期分離。
- 原始公告連結。
- 重大異動站內通知。
- 人工確認及處理狀態。

**官方來源**

- https://www.thb.gov.tw/cp.aspx?n=12588
- https://traffic.tainan.gov.tw/StaticPage/HeavyTruckAndArticulatedVehicleRoutes

優先研究高雄、臺南、屏東及常用運輸區域，再評估其他縣市。

**待研究事項**

- 是否存在統一的政府開放資料集或 API。
- HTML、PDF、附件等資料的更新偵測方式。
- 官方網站是否允許程式化擷取。
- 如何避免版面更新造成誤報。
- 如何區分草案、正式公告、廢止與生效中的規定。
- 如何降低地方政府網站改版造成的維護成本。

**第一版建議**

只監控公告異動，不自動解讀法規、不自動判定車輛可以通行。

### RFC-03｜柴油牌價與營運成本

**目的**

利用中油官方牌價建立低維護成本的燃料價格及成本參考模組。

**候選功能**

- 最新柴油牌價。
- 每週漲跌幅。
- 歷史油價紀錄。
- 油價異動通知。
- 每公里燃料成本試算。
- 單趟運輸燃料成本試算。

**官方來源**

- https://data.gov.tw/dataset/6339
- https://vipmbr.cpc.com.tw/openData/swagger/index.html
- https://vipmbr.cpc.com.tw/openData/swagger/v1/swagger.json

**待研究事項**

- 實際 API 端點與資料格式。
- 是否需要認證及是否有呼叫限制。
- 油價生效日期與資料更新時間。
- 如何避免重複儲存相同價格。
- 是否有可合法取得的歷史資料。

**第一版建議**

只做官方牌價同步、歷史紀錄及簡單試算。

不直接修改 ERP 財務帳務、正式報價或既有合約。

### RFC-04｜運輸及吊裝作業氣象情報

**目的**

為大型機件運輸與吊裝作業提供氣象風險參考，而不是單純顯示一般天氣資訊。

**候選功能**

- 指定作業地點氣象預報。
- 測站風速。
- 最大瞬間風速。
- 降雨量。
- 豪雨及颱風警特報。
- 預定作業時段的氣象資訊。
- 可設定的內部氣象注意門檻。

**官方來源**

- https://opendata.cwa.gov.tw/
- https://opendata.cwa.gov.tw/dist/opendata-swagger.html

**待研究事項**

- 適用的測站及預報資料集。
- 免費 API Key 額度與更新頻率。
- 測站座標與作業地點的配對方式。
- 預報、實測與瞬間風速的差異。
- 與 RFC-01 災害示警的功能重疊。
- 資料缺漏及測站距離過遠的處理。

**安全限制**

氣象資料僅供風險參考。

不得使用單一氣象測站或固定通用風速門檻，自動核准吊裝作業。實際作業仍須遵循設備規範、現場量測及安全管理程序。

### RFC-05｜橋梁與高風險路段資料庫

**目的**

建立重件運輸使用的道路設施與現勘知識索引。

**候選功能**

- 官方橋梁監控資料。
- 高風險道路監控資料。
- 國道、省道道路中線。
- 道路名稱、樁號與座標。
- 管轄機關資訊。
- 人工現勘紀錄。
- 限高、限寬、限重紀錄。
- 資料來源、確認日期及可信度。
- 已知風險路段查詢。

**官方來源**

- https://data.gov.tw/dataset/16195
- https://data.gov.tw/dataset/16194
- https://data.gov.tw/dataset/73232

**待研究事項**

- 官方資料實際欄位、覆蓋範圍及更新頻率。
- 座標系統及道路樁號匹配方式。
- 是否可使用現有資料庫完成空間索引。
- 是否真的需要 PostGIS 等額外服務。
- 官方資料與人工現勘資料的分離方式。
- 過期現勘紀錄的提醒機制。
- 如何與 permit-knowledge 分支的道路及橋梁知識互相參照。

**安全限制**

橋梁監控資料不等於橋梁承載能力證明。

不得將缺少限制資料解讀為不限重、可通行或已取得主管機關核准。

**第一版建議**

先做可查詢的風險索引及人工現勘紀錄，不導入大型 GIS 架構或自動導航。

---

### RFC-06｜國道通行費與運輸報價試算

**目的**

建立可離線運作、具備計算依據的國道通行費及運輸成本參考工具。

**候選功能**

- 車種分類。
- 行駛距離。
- 每日優惠里程。
- 差別費率。
- 特殊收費政策。
- 國道通行費試算。
- 與 RFC-03 柴油牌價結合的成本試算。

**官方來源**

- https://www.freeway.gov.tw/etc/publish.aspx?NID=1941&P=9102
- 高速公路局其他正式收費公告。

**待研究事項**

- 現行大型車及聯結車收費分類。
- 每日累計里程與單趟試算的差異。
- 優惠及特殊費率適用條件。
- 費率生效日期與版本管理。
- 國道通行費試算與實際帳單的差異。
- 是否需要外部路線 API，或人工輸入里程即可。

**第一版建議**

先使用官方費率與人工輸入里程進行本機計算，不依賴付費地圖 API。

所有試算結果須標示假設條件，不作為正式 ETC 帳單或財務憑證。

### RFC-07｜車輛維修、油耗與保養紀錄

**目的**

優先利用 Frappe 生態系已有的成熟功能，避免重複開發。

**候選功能**

- 維修及保養紀錄。
- 里程表紀錄。
- 加油量及油耗。
- 維修及燃料支出。
- 下次保養日期或里程提醒。
- 車輛歷史成本查詢。
- 與既有車籍及提醒系統整合。

**官方開源來源**

- https://docs.frappe.io/hr/vehicle-log
- https://docs.frappe.io/hr/vehicle
- https://github.com/frappe/hrms

**待研究事項**

- Frappe HRMS 與目前 Frappe v15 的版本相容性。
- vsd_fleet_ms 是否已有相同或類似功能。
- Vehicle Log 與 Truck、Trailers 等 DocType 的資料模型差異。
- 是否需要安裝完整 HRMS。
- 是否能以較小的相容性整合方式重用現有功能。
- 權限、授權、升級及維護成本。
- 如何避免重複建立車輛主檔。

**第一版建議**

先盤點既有 ERP 功能，不預設需要新增 HRMS 或自行開發完整維修模組。

## 4. 共用架構要求

所有候選功能應遵守：

1. 保留 ERP 容器既有網路隔離。
2. 外部連線只能經由受控 gov-egress。
3. 每個資料來源必須具有獨立的固定上游白名單。
4. 僅開放實際必要的 API 路徑、HTTP 方法及查詢參數。
5. 不提供任意 URL、通用 Proxy 或 CONNECT 隧道。
6. 驗證 TLS，限制回應大小、逾時、併發及重試。
7. 金鑰不得寫入 Git、前端、日誌或代理提示詞。
8. 不因 API 失敗而刪除上一次成功取得的資料。
9. 顯示最後成功更新時間及資料有效狀態。
10. 避免重複通知及首次同步通知洗版。
11. 新資料來源應保持模組化，不將全部功能塞入 road_events.py。
12. 正式營運不依賴任何 AI 模型、訂閱帳號或付費推論服務。
13. 不安裝來路不明或缺少明確授權的第三方軟體。
14. 優先採用現有依賴套件與官方開源元件。
15. 未經授權不得開放新的正式環境網路權限。

不要求為了七項候選功能提前建立大型通用框架。應在確認實際共用需求後，再提取必要的共用元件。

## 5. 多模型審查分工

### Claude｜總工頭

- 盤點 Fleet Center 現有程式及正式環境架構。
- 確認七項功能是否重複既有 ERP 功能。
- 評估最小可行實作。
- 統整其他模型的技術建議。
- 提出最終開發順序及獨立 PR 拆分方案。

### Gemini｜官方資料與技術研究

- 查證七項功能的官方來源。
- 確認 API、資料集及授權。
- 確認免費額度、認證及商用限制。
- 檢查資料實際覆蓋範圍。
- 尋找成本更低、維護更簡單的官方替代方案。
- 提供可追溯的證據及來源網址。

### GPT Codex｜工程與安全審計

- 檢查現有程式的可重用程度。
- 審查資料模型及模組邊界。
- 審查網路隔離及出口代理設計。
- 評估排程、通知、錯誤處理及回歸測試。
- 找出容易造成技術債、誤報或資料失真的設計。
- 評估是否存在更簡單的實作方式。

其他 AI 不應直接接受總工頭的假設，應獨立提出反對意見及替代方案。

### 人工中繼規則

Claude 不得直接呼叫 Gemini CLI 或 GPT Codex CLI。

所有跨模型任務均由 Claude 撰寫獨立提示詞，再由使用者手動複製到官方互動式 CLI。

禁止透過第三方代理、SDK、Shell Script、MCP Bridge 或其他自動化方式轉用 AI 訂閱憑證。

## 6. 審查回報格式

每個模型應逐項回報：

| 評估項目 | 說明 |
|---|---|
| RFC 編號 | RFC-01 至 RFC-07 |
| 營運價值 | 實際解決什麼問題 |
| 官方來源 | 可追溯網址及查證結果 |
| 免費使用 | 額度、授權及限制 |
| 資料完整性 | 已知缺口 |
| 現有功能重疊 | 是否已具備類似能力 |
| 可重用程式 | 具體檔案或模組 |
| 必要依賴 | 新套件、新服務或無 |
| 資安影響 | 網路及權限變更 |
| 開發成本 | 低、中、高及理由 |
| 維護成本 | 長期運作負擔 |
| 最小可行版本 | 第一版必要功能 |
| 驗收方式 | 可實際執行的測試 |
| 尚未確認 | 不得假裝已驗證 |
| 最終建議 | 採用、修改、延後或放棄 |

如果某項功能缺少可信資料、與既有功能重疊，或維護成本明顯高於營運效益，可以建議放棄。

不要求七項全部實作。

## 8. 本輪停止條件

完成七項候選功能的技術研究、獨立審查及實作拆分建議後停止。

本輪禁止：

- 實作新功能。
- 修改正式程式。
- 安裝新套件。
- 修改正式資料庫。
- 調整正式防火牆。
- 開放新 API 網域。
- 購買服務。
- 自動提交或合併 PR。
- 擅自部署正式環境。

所有建議交由使用者裁決。

審查目標不是增加最多功能，而是在可信資料來源、低營運成本、可維護性及既有安全邊界下，找出最值得實作的功能。
